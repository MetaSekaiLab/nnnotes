nnnotes 0.3.0

Persistent depots store task inputs, content-addressed results, catalog versions and retained runs, with optional S3-compatible remote storage. Commands reuse verified task results and manage source downloads under a configurable budget and command leases.

Catalog versions and labels are shared through the remote. Census planning, emitted task descriptions and standalone task results retain the content they need through collection, including completed results from interrupted pipelines.

Live2D, room, spot, live, story and UI exports use shared object products. Named site builds publish assets, product manifests and indexes in dependency order, preserve unselected regional topics and restore complete layouts from depot records.

Standalone episode, shader and audio exports also reuse depot tasks. Command records retain accessed results and content. Collection protects recent results and their dependencies for a configurable grace period, and remote verification reads remote-only content without populating the local cache.

PNG and font task keys include the native compression library identity, so stored results are shared only between matching encoder implementations.

S3 collection follows paginated listings, batches deletion requests and reports per-object deletion failures.

Configuration and command interface:
- Set [paths] depot and, when needed, [depot] remote.
- Use depot plan, depot run, depot verify and depot gc to manage stored work.
- Use site build --name NAME -o DIR for a named site and bundle pull -o DIR for source bundle copies.
- Product playback uses ournotes-player 0.2.x. Story and UI data use the documented nnnotes.product/1 formats.
- The deck extra pins ournotes-sim 0.0.12.

See the configuration, depot, products and site references for command options and data contracts.
